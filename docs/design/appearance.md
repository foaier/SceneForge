# SceneForge 工具外观与界面设计规范

## 1. 文档目的

本文定义 SceneForge 桌面工具的视觉方向、界面层级、主要工作区布局、交互反馈和可访问性要求，作为后续界面设计与评审的产品设计依据。

本文只描述用户可见的页面、视觉层级和交互反馈，不指定代码结构、组件实现、媒体引擎或服务接口。本文覆盖 [RFC-001 至 RFC-008](../../spec/rfc-001-ai-short-drama-production.md) 定义的完整目标产品；所列工作区不表示会在同一版本交付，也不改变经确认的发布范围。尺寸、色彩和布局是可评审的设计基线，需通过界面原型和真实创作任务验证后再冻结。

## 2. 设计目标

SceneForge 面向个人创作者和编剧，帮助用户把创意逐步整理为创作圣经、剧本、分镜和参考图。界面应让新手能从一句想法开始，也让熟悉创作流程的用户可以快速编辑大量内容。

设计需要同时满足以下目标：

- 工作状态清楚：用户能看出当前作品、剧集、场次、选中内容、保存状态和待处理任务。
- 内容优先：剧本、分镜和参考图是界面主体，不被装饰、宣传内容或不必要的面板挤压。
- 逐步展开：常用操作容易发现，专业字段和高级选项按需展开。
- 修改可控：AI 生成、改写、检查和导出结果都有清楚的预览与确认位置。
- 离线可理解：网络或 AI 服务不可用时，明确哪些本地操作仍可继续。
- 稳定可读：长时间阅读、撰写、比较候选和整理素材时保持清晰层级与舒适密度。

## 3. 视觉方向

### 3.1 总体风格

参考 DaVinci Resolve 的专业剪辑工作台观感：深色中性面板、黑色媒体监看区、克制的选中高亮和按轨道类型区分的时间线色块。SceneForge 参考其整体明暗关系与专业工具的视觉密度，不照搬品牌元素或具体工作区设计；主要操作采用中性浅灰高亮，暖橙只用于少量创作强调，状态色按语义分别使用。文字编辑、分镜审核和素材整理仍需保持长时间使用的清晰度。

它应像一件用于持续工作的创作工具，而不是视频平台、营销网站或概念展示页。进入应用后优先显示作品资料库或上次打开的创作工作区，不显示宣传式首页。

### 3.2 视觉原则

- **内容优先**：文字、镜头和素材是视觉焦点；工具栏和辅助信息保持克制。
- **以层级代替卡片堆叠**：通过留白、分隔线、标题和背景层次区分区域；卡片只用于候选、素材等需要独立比较的重复对象。
- **状态始终可辨**：保存、待确认、已确认、可能过期、受限和失败等状态使用文字与图形共同表达，不只依靠颜色。
- **渐进披露**：新手常用字段优先；完整镜头参数、生成限制和权利细节可在检查器中展开。
- **编辑与审核分开**：正式内容、AI 候选、检查提示和来源信息使用一致但可辨的视觉语义。
- **操作反馈明确**：长任务、后台任务和保存状态不依赖短暂的 Toast 作为唯一反馈。

## 4. 信息架构与主窗口

### 4.1 全局导航

主导航分为资料库级入口和作品内入口。打开作品后，侧边导航展示：

| 分组 | 入口 | 内容 |
|---|---|---|
| 总览 | 概览 | 作品信息、进度摘要、最近编辑内容和待处理事项 |
| 创作 | 创作圣经 | 角色、地点、道具、故事规则、视觉基调和参考资料 |
| 创作 | 故事与剧本 | 故事简报、梗概、分集大纲、场次大纲和剧本 |
| 创作 | 分镜 | 场次列表、镜头板、镜头时长和视觉参考 |
| 制作 | 视频与动画 | 单镜头/批量生成、动画和候选审核 |
| 制作 | 声音 | 对白、配音、音乐、音效和口型同步 |
| 制作 | 字幕与语言 | 字幕编辑、翻译和语言版本对照 |
| 制作 | 剪辑与特效 | 时间线、剪辑、声音后期、调色和特效 |
| 管理 | 素材 | 导入素材、生成候选、派生素材、来源和授权信息 |
| 管理 | 检查 | 一致性、内容质量、风险提示和处理状态 |
| 管理 | 交付 | 成片、剧本、分镜和作品资料包的选择与导出 |

设置和资料库切换位于应用级区域，不混入作品内容导航。分组用于帮助扫描，不强制用户按从创作到制作再到交付的顺序操作。

### 4.2 主窗口分区

建议的桌面工作区由以下区域组成：

```text
┌──────────────────────────────────────────────────────────────────────┐
│ 应用栏：资料库 / 作品名 / 剧集 / 保存状态 / 全局任务 / 设置           │
├──────────────┬───────────────────────────────────┬───────────────────┤
│ 作品导航     │ 当前工作区                         │ 上下文面板         │
│              │ 剧本、分镜、素材或检查结果         │ 检查器 | 助手      │
│              │                                   │ 当前对象详情或提问 │
├──────────────┴───────────────────────────────────┴───────────────────┤
│ 可折叠任务栏：AI 生成、媒体探测、导出及失败/完成状态                 │
└──────────────────────────────────────────────────────────────────────┘
```

尺寸均以逻辑像素表示，指界面布局尺寸而非物理屏幕像素；推荐原型评审窗口为 1440 × 900，并在 1280 × 720 下验证密集工作区。应用栏约 56 px，左侧导航约 224 px，右侧面板约 320 px，中间主内容目标宽度约 640 px。窗口宽度按以下断点适配：宽度不小于 1280 px 时显示三栏；960–1279 px 时右侧面板默认收起、按需打开抽屉；720–959 px 时左侧导航缩为约 56 px 图标栏、右侧面板收起；小于 720 px 时两侧面板均改为临时抽屉，主内容使用单栏布局。窗口高度低于 640 px 时应用栏收为紧凑样式，内容区滚动，保存状态和当前主要操作仍可访问。任何尺寸下都不得出现面板重叠、内容被裁断或唯一操作只存在于悬停状态。以上是原型验证断点，不代表最终最低系统配置。

### 4.3 应用栏与上下文

应用栏持续呈现当前资料库、作品名称、当前剧集或位置，以及最近保存状态。当前作品标题可点击进入作品概览；路径和内部 ID 不作为主视觉信息。

全局任务入口显示待确认任务数、执行中任务数或失败提醒。任务栏默认收起，用户展开后可检查进度、输入范围、结果和下一步操作。任务数量变化不应使主工作区跳动。右侧上下文面板为一个可收起区域，检查器和助手通过标签切换；同一时刻只显示一个，避免在不同页面出现互不一致的并排布局。页面需要检查器时默认选中检查器；用户可切换至助手，切换页面后按页面记忆最近使用的标签。

## 5. 主要页面外观

### 5.1 资料库与新建入口

资料库采用便于扫描的项目列表作为默认视图，可切换缩略图视图。每项显示作品名称、作品类型、剧集数量、最近编辑时间、作品保存状态和素材缺失状态；两种状态分别标记，不合并成一个“保存/缺失”提示。不以大尺寸封面图挤占首屏空间。

新建作品入口并列提供三种清晰操作：从创意开始、导入已有剧本、从空白或模板开始。选择后进入可跳过的引导流程；用户可以随时切换到自由编辑。引导字段分组填写，不要求用户在创建时补完所有设定。

### 5.2 作品概览

作品概览以作品名称和当前创作阶段为首屏信号，随后展示最近编辑的剧本/分镜、待确认候选、未处理检查和缺失素材。使用简洁清单呈现可继续的工作，不用装饰性图表或大块空白卡片。

### 5.3 创作圣经

左侧使用分类目录切换角色、地点、道具、规则和视觉基调；中间区域展示选中条目的内容和参考资料；检查器显示确定状态、来源、关联对象和版本信息。

“确定”“暂定”“待决定”和“禁止改变”以明确文字标签和对应图形呈现。AI 对设定的建议在独立候选区比较，不能与正式设定混排为同一内容。

### 5.4 故事与剧本

剧本工作区建议采用三栏：集/场次大纲、正文编辑区、检查器/上下文助手。正文获得最大宽度和视觉权重。大纲可以折叠；检查器与助手共用右侧区域，通过标签切换，避免同时打开时挤占正文。

剧本结构使用稳定的段落视觉样式区分场景标题、动作、角色提示、对白、旁白、音效和转场。正文编辑以阅读连续性为主；打印预览可以采用独立版式，但不改变编辑视图中的内容结构。

版本比较使用并排或逐段差异视图。新增、删除和修改应有文字标记与差异说明；用户可逐段采用、拒绝或保留为独立版本。

### 5.5 分镜与镜头板

分镜区以场次为主线，可在镜头列表和视觉板两种视图间切换。镜头列表适合快速调整顺序和字段；视觉板适合查看参考图、构图和连续性。两种视图编辑同一组数据，不形成彼此独立的副本。

每个镜头的缩略图、编号、时长、审核状态和剧本关联应保持稳定位置。选中镜头后，检查器展示专业字段；新手可切换到自然语言简化编辑，不丢失已填写信息。

当上游剧本或角色设定变化时，在受影响镜头附近显示“可能过期”及影响来源。提示可定位，不自动重写镜头或替换参考图。

### 5.6 候选审核

图片、文本或后续视频候选进入统一的候选审核视图。候选区应显示其目标对象、生成服务、生成时间、使用上下文、已知限制和来源状态；比较视图提供并排预览、切换查看和差异摘要。

接受、部分采用、拒绝和重试是明确的操作。接受前保持正式内容不变；拒绝或生成失败时保留既有确认内容。涉及外部服务的数据发送确认在任务提交前单独完成，不与候选接受操作混为一谈。

### 5.7 素材、来源与授权

素材库提供列表/缩略图视图、类型筛选、引用位置和来源状态。单项详情区分用户填写信息、系统观察信息和未知信息；授权状态显示为清楚的文本和图形，不把“待确认”呈现成已授权。

用户可以从素材详情跳转到其关联角色、场次、镜头或交付版本。外部引用缺失时保留原引用位置并提供重新定位入口。

### 5.8 检查结果

检查页按错误、警告、信息分组，并支持按作品位置、规则类型和处理状态筛选。每条结果说明影响内容、依据、判断来源、不确定性和可采取动作；选择结果后能跳转到相关正文、镜头或素材。

错误、警告和普通提示使用图标、文字和颜色共同区分。一般创作建议不使用阻断式红色警报，也不默认挡住保存或导出。尚未检查、检查失败和检查通过是不同状态。

### 5.9 交付与导出预览

交付区允许用户为同一作品添加一个或多个交付目标，分别选择单集/全剧、地区/平台或自定义预设、画幅和交付内容。用户可以并列比较不同版本的参数、差异和风险；每个版本独立保留，生成一个版本不得覆盖其他版本或源剪辑。中国与海外平台预设使用相同的信息层级。每项参数应标明属于“平台要求”“产品建议”还是“用户自定义”；有可用依据时显示适用场景、来源和核实时间。来源缺失、适用情况不清或信息过期时，明确显示“未知”“待核实”或“已过期”，不得呈现为当前已满足平台要求。界面应说明这些预设用于准备和对照，不保证平台审核通过。

“已核实”“建议模板”“待核实”“已过期”等状态不能只靠颜色区分。文件级 AI 标识与来源凭证是不同项目，交付摘要应分别显示。用户自定义的值应能与预设建议分辨，覆盖参数时提示其影响范围，但不自动改写作品。

风险摘要分为可忽略的一般提示与必须处理的适用交付要求；说明结果范围，不承诺平台审核通过。

导出设置按画面、声音、字幕/语言、来源/标识和交付文件分组，明确显示画幅、实际分辨率、帧率、编码格式、音频采样率/声道、语言和包含内容；不以“高清”或“高质量”代替具体值。剧本导出提供适合编辑、打印和通用交换的模板预览。执行导出后可从任务栏查看进度、失败原因和已完成结果；导出失败不覆盖作品或清除已完成资料。

### 5.10 视频与动画生成

生成工作区以场次/镜头清单和预览区为主。镜头清单显示镜头编号、时长、参考图、生成状态和审核状态；预览区显示当前确认素材或候选。单镜头生成时，当前镜头信息与生成条件可在右侧检查器查看；批量生成时，镜头清单同时呈现排队、处理中、失败、已完成和待审核状态，并允许逐项进入审核。

生成条件按“画面描述、角色/场景参考、运动与时长、画幅、服务及限制”分组。视觉类型明确列出实拍感、二维动画、三维动画和动态漫画；动态漫画还需能查看画格顺序及运动元素。新手可以编辑自然语言摘要，专业用户可展开镜头字段；两者指向同一份生成要求。提交前用清单呈现目标镜头、使用的上下文、生成数量和可获知的限制。候选以并排或逐个切换的方式比较，提供播放、局部重做、保留为备选、接受和拒绝；批量完成不得使候选自动变成正式镜头。

### 5.11 对白、声音与口型

声音工作区以对白列表为主线，按角色、语言和场次筛选。每句对白附近显示文本、角色、语言、声音设定、时长和候选状态；选中后可试听并比较多个表演候选。声音来源和授权信息放在可展开的详情区，授权待确认或已撤销时使用清楚的文字状态，不以试听按钮暗示可以继续生成。建立可复用的克隆声音前，单独呈现授权范围、用途和期限确认；不得把一般外部服务授权当作声音本人授权。

音乐、环境声、音效和对白以分组轨道或分组列表呈现，可分别试听和调整。混音预览应能让用户识别当前正在听到的声音类别，并显示对白清晰度、音画同步等检查结果。口型同步以句子或镜头为单位显示视频帧与对白音频的对齐预览，允许调整句子范围和角色归属；重做某句时清楚标出影响范围。

### 5.12 字幕与语言版本

字幕编辑区采用逐句列表与视频预览并列的布局。列表列出时间位置、说话人、字幕内容、语言和检查状态；选中字幕后，预览定位到对应画面，并显示安全区、遮挡和行长提示。用户可以直接编辑字幕，也可以使用时间轴查看字幕间隔和重叠。字幕用途可选择逐字稿、对白、无障碍描述或简洁发布等样式，当前用途应始终可见。

翻译与本地化使用原文/译文对照视图，按句对齐；原文与译文通过不同列和语言标签区分，不允许在视觉上误认为一份可互相覆盖的文本。候选翻译提供逐句接受、拒绝和重译入口。语言版本、字幕样式和声音版本可分别切换，切换时持续显示当前语言，避免误改其他语言版本。

### 5.13 剪辑时间线

剪辑工作区采用“媒体/场次浏览区、成片预览区、多轨时间线、属性检查器”的结构。预览区保持稳定比例并优先显示画面；时间线位于下方并可调整高度；媒体和场次浏览区可收起；检查器显示选中片段或轨道的属性。时间线至少区分视频、声音、字幕和图形轨道，并显示轨道名称、锁定/静音/隐藏状态及时间标尺。

选中片段后，应能同时看出其时间范围、来源镜头或素材、关联字幕/声音和版本。时间位置可按帧或时间码读取；播放、逐帧移动、循环预览和时间标记操作位置固定。剪切、删除、移动和覆盖等动作在操作前说明影响的片段或轨道；撤销/重做入口始终可见或可通过标准菜单访问。

多机位视图应把各机位预览与主播放画面区分清楚，并显示当前选中机位；切换机位不能改变用户对主时间线状态的理解。代理素材、原始素材、画幅/帧率差异和色彩信息通过可识别状态提示呈现，不以无法辨认的技术缩写作为唯一说明。

### 5.14 特效、调色与媒体工具

特效和调色操作围绕当前片段的检查器展开。效果按可读名称列成有序列表，可调整作用范围、开关、顺序和参数；处理前后比较使用明确的分屏、切换或对照预览。关键帧应在时间线上与效果名称关联，避免只显示无标签的菱形标记。运动跟踪、复杂遮罩和抠像应在预览区标示跟踪目标、遮罩边界或透明区域，并提供定位到待修正位置的结果列表。

调色视图应同时让用户查看画面和亮度/色彩分析视图，并提供波形图、矢量示波器和直方图中的至少两种；素材色彩信息、当前预览状态和目标输出状态需分开呈现。关闭效果、重置当前参数或恢复处理前状态的操作容易找到，且不与删除源素材混淆。

媒体探测、抽帧、转码或批量处理使用任务列表呈现输入文件、识别属性、目标操作、输出位置和处理状态。抽帧预览显示源文件和时间位置；批量任务逐项显示成功、失败、取消和待处理状态。工具页明确区分只读探测、生成新素材和可能覆盖输出的操作，并在开始前预览范围与结果位置。

### 5.15 工作区共用规则

视频生成、声音、字幕、剪辑和媒体工具沿用相同的应用栏、上下文面板、候选审核、任务状态、来源/授权状态和错误反馈。各工作区可根据画面、音频或时间线任务调整内容分区，但不另创一套保存、候选、来源和授权的视觉语义。

### 5.16 服务与应用设置

设置按文本、图像、视频、声音等能力分组，显示各能力当前默认服务、服务状态、连接类型和用户可获知的限制。用户能够分辨本地服务与外部服务，并在单次生成任务中临时更换服务；临时切换入口应出现在任务提交前的确认区，不要求用户离开当前创作页面。

授权管理按服务列出已授权、未授权和已撤销状态，并提供查看本次数据范围或撤销授权的入口。已知费用、额度、数据保存或训练使用信息显示其来源和状态；未知信息不得使用绿色安全标识或承诺式文案。设置变更应明确显示适用能力和后续任务范围，不让用户误以为改变默认服务会改写已有作品或已提交任务。

## 6. 视觉语言与组件规则

### 6.1 色彩

深色主题作为主视觉基线：应用画布和工作面采用不同明度的中性炭灰色，媒体监看区接近黑色，避免整屏纯黑。主要操作使用中性浅灰高亮，暖橙用于生成/创作强调，蓝色用于信息与链接，绿、琥珀、红分别表达成功、警告和错误。时间线使用低饱和度色块区分视频、声音、字幕/图形轨道；片段文字和选中状态仍须清楚可读。色彩只辅助识别，不能独立承担状态含义。

| 颜色角色 | 建议色值 | 用途 |
|---|---|---|
| 工作区背景 | `#1E2023` | 主窗口背景 |
| 内容面 | `#282A2E` | 编辑器、列表和工具面板 |
| 浮层/选中面 | `#32353A` | 当前分组、下拉面板和次级工作区 |
| 媒体监看区 | `#090A0C` | 视频和图像预览底色 |
| 正文 | `#ECEFF3` | 标题、正文和主要图标 |
| 次级文字 | `#B3BAC3` | 辅助说明和次要元信息 |
| 轻分隔线 | `#41464D` | 非交互面板分区和表格行分隔 |
| 控件边界 | `#828A95` | 输入框、选择控件等需要识别的边界 |
| 主操作 | `#B8C0C8` | 创建、确认等主要操作；按钮文字用深色 |
| 主操作文字 | `#202124` | 浅灰主操作按钮上的文字和图标 |
| 选中背景 | `#35413E` | 当前导航或选中行；同时显示浅灰边线/标记 |

颜色值是首轮建议，具体前景/背景配对需在最终组件状态中核对。普通文字至少达到 4.5:1，必要的控件边界和图形至少达到 3:1；轻分隔线只用于不承载交互含义的分区。浅灰主操作按钮使用深色文字；状态文字使用高对比度的状态色，同时保留标签或图标。时间线片段使用浅色文字，并保留足够的片段间隔和选中边线。暖橙用于深色面上的局部强调，不用于大面积背景。禁用状态不能仅通过降低透明度表达。深色界面应在监看区、缩略图和调色画面周围保留中性背景，避免界面色偏影响用户判断画面。

### 6.2 字体与层级

界面优先使用系统 UI 字体，确保中文显示清晰并支持中英文混排。尺寸均为逻辑像素：正文建议 14–16 px，辅助信息不低于 12 px，页面标题 20–24 px；不得通过过小字号塞入过多字段。系统缩放和文字放大后应重新检查布局，不得按物理屏幕像素固定字体大小。

剧本正文使用舒适行宽和稳定行距。打印剧本和屏幕编辑器可以使用不同字形/排版规则，但必须保留相同内容语义。长文本可调字号和缩放。

### 6.3 间距、边界和图标

- 使用 4 px 基础间距单位，常用间距为 8、12、16、24 和 32 px。
- 内容区域以平直、清晰的面板为主；重复素材、候选和项目条目可使用 4–8 px 小圆角。
- 避免大面积投影、渐变装饰、悬浮气泡和多层嵌套卡片。
- 图标采用一致的线性风格；图标按钮必须有可访问名称，且在鼠标悬停和键盘聚焦时均显示说明提示；核心操作不只依赖提示文字传达其名称。
- 主要命令使用图标加文字；工具栏中的撤销、重做、放大和视图切换可使用有提示的图标按钮。
- 单选模式用分段控件；二元设置用开关或复选框；数值用输入框/步进控件；多个视图用标签；过滤和批量动作使用可读菜单。

## 7. 交互反馈与状态

### 7.1 保存状态

应用栏显示“保存中”“已保存”和“保存失败”。保存失败时说明未保存的修改仍在哪里、用户应采取什么行动；不能只用短暂提示消失。

### 7.2 AI 与后台任务

任务开始前展示服务、目标、上下文范围和可获知的限制。运行中显示状态和可取消操作；取消后说明哪些结果保留、外部服务是否可能已收到请求。任务完成后提供查看结果的入口。

外部请求确认使用独立的提交前页面或对话框：列出服务名称与实际数据接收方、任务用途、发送的文本与素材、已知的数据保存或训练信息及未知项。首次使用时取得该服务的授权；后续每次仍展示本次范围。用户可移除上下文、取消或改用其他服务。请求提交后取消时，不得暗示服务端未收到或已删除数据。

### 7.3 确认与破坏性操作

接受候选、删除作品、替换唯一素材或覆盖已有输出时，确认文案应说明具体对象和影响范围。一般导航和可撤销编辑不使用重复确认弹窗。

### 7.4 空、错和等待状态

空状态给出当前页面最相关的下一步操作；错误状态说明受影响对象、是否保留输入和结果、可采取的处理方式；等待状态显示正在进行的步骤。无 AI 服务或离线时，仍突出可用的手工操作。

## 8. 可访问性与窗口适配

- 将 WCAG 2.2 AA 的适用准则作为对比度、键盘操作和信息可感知性的可访问性目标；本文不表示产品已通过认证或整体合规评估。
- 所有主要操作支持键盘完成；焦点顺序符合页面阅读顺序，焦点轮廓清楚可见。
- 控件名称、状态、错误和选择结果可被辅助技术识别；不能依赖悬停作为唯一操作方式。
- 状态、选择、风险等级和差异不能只靠颜色或位置表达。
- 支持操作系统缩放与文字放大；放大后导航、检查器和弹窗仍能访问，不遮挡正文或关键操作。
- 镜头板和时间线的拖放操作必须有可发现的键盘或菜单替代路径。镜头板支持以焦点选择镜头、用方向键移动焦点，并通过明确的“上移/下移/移至场次”命令调整顺序；时间线支持选择片段、按帧移动边界、移动片段和访问片段菜单。快捷键可以加速操作，但命令菜单和焦点状态不能依赖快捷键记忆。
- 窗口尺寸变化时允许折叠辅助面板和导航；核心编辑内容和确认操作不得被隐藏或重叠。

## 9. 设计验收清单

每个主要页面评审时至少确认：

1. 当前作品、位置和保存状态是否一眼可见。
2. 主内容是否占据足够空间，辅助面板是否可收起。
3. 新手能否找到下一步，熟练用户能否直接编辑。
4. 正式内容、候选、建议和风险是否清楚区分。
5. 键盘、焦点、缩放和辅助技术状态是否可用。
6. 离线、任务失败、素材缺失和保存失败时是否仍有明确反馈。
7. 窄窗口下是否没有文字溢出、控件重叠或关键操作被遮挡。
8. 检查器和助手是否遵循同一面板切换规则，窄窗口和缩放状态下仍可到达。
9. 分镜排序、候选审核和时间线关键操作是否有不依赖拖放的可见路径。

## 10. 待原型验证

- 资料库默认使用列表还是缩略图视图。
- 1440 × 900 和 1280 × 720 下的导航/检查器实际宽度与折叠行为，以及更窄窗口下抽屉模式的可用性。
- 剧本正文最舒适的字体、行宽和行距。
- 低饱和度轨道色块与时间线选中边线在不同显示器、缩放和长时间剪辑条件下的辨识度。
- 分镜视觉板在不同镜头数量和缩放级别下的焦点移动与键盘排序操作。

以上事项不阻止形成首版视觉方向，但在主窗口和剧本/分镜高保真原型评审后应记录决策与变化。
