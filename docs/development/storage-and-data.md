# 项目存储与数据模型

## 1. 用户可见存储方式

用户在设置中选择作品资料库目录，例如 `D:\SceneForgeProjects`。TASK-R002-000 原型验证后，首阶段采用“每个作品独立目录、数据库与媒体文件分开保存”的布局。首阶段只承诺本机 NTFS 路径和单个应用进程写入；网络共享、同步盘、可移动磁盘、跨卷移动和多进程同时写同一作品不属于支持范围。需要交接或备份时，用户导出一个可移交资料包；日常工作目录和交付资料包是两种不同用途。

```text
<用户选择的资料库目录>/
  <作品目录>/
    project.sqlite
    media/
      originals/
      generated/
      derived/
    thumbnails/
    exports/
    temp/
```

`temp/` 可清理且不得作为唯一内容存储；缩略图可重建。数据库、原始素材、生成候选和已确认导出不可按缓存规则清理。

## 2. 导入素材

为避免断链，普通导入默认将素材复制到作品目录并保留原始文件。进阶用户可以选择引用外部原文件以节省空间；引用模式必须显示原路径，发现原文件不可用时将资产标记为缺失并提供重新定位，不能静默删除关联。作品资料包若包含外部引用资产，默认打包该资产的副本，不移动或修改原文件；因文件缺失、权限或用户选择而未打包的项目，必须在导出清单中列明，并在恢复后保留为缺失/外部引用状态。

每项资产拥有稳定 ID、素材类型、来源类型、创建时间、内容摘要、媒体属性、权利状态和生成/编辑关系。导入文件名不是资产身份。重命名或在作品内移动文件不得改变引用关系。

## 3. 元数据与文件布局

SQLite 保存结构化、可查询的数据；媒体二进制文件独立存放。建议实体如下：

| 实体 | 关键内容 |
|---|---|
| Project / Episode | 作品类型、名称、全剧/单集目标信息、稳定集 ID、顺序、草稿/已确认/模板建议状态、修改快照 |
| BibleItem | 角色、地点、道具、规则、确定状态、来源与变更影响 |
| ScriptBlock / ScriptVersion | 场景标题、动作、角色、对白、顺序、版本快照 |
| Scene / Shot | 场次、镜头、持续时间、构图/动作描述、剧本关联 |
| Asset / AssetRelation | 文件 URI、内容哈希、原始/派生关系、镜头引用 |
| RightsRecord | 来源、作者、许可、限制、期限、用户填写或系统观察来源 |
| GenerationTask / Candidate | 能力、服务引用、上下文清单、状态、候选结果和确认状态 |
| CheckResult | 检查范围、规则版本、依据、定位、风险等级及用户处理状态 |
| ExportJob / PackageManifest | 导出选择、目标格式、结果清单、文件校验信息 |

生成服务凭据、API 密钥和账户令牌不写入 SQLite，也不进入作品导出包。

## 4. 保存、版本和迁移

- 正式内容自动保存并显示最近保存状态；应用退出前仍提示未保存内容。
- 草稿自动保存与已确认版本分开。用户接受 AI 候选时建立新的正式内容版本，不就地覆盖旧版本。
- 版本恢复创建新版本并保留被恢复版本；恢复前显示影响到的剧集、剧本、场次、镜头和引用资产。
- 数据库采用显式 schema 版本和顺序迁移。迁移前自动创建可恢复的一致性备份；使用 WAL 时不得仅复制主数据库文件作为备份，必须通过 SQLite 在线备份 API、受控检查点与写入隔离，或等效方式纳入已提交事务。迁移失败回滚，不留下部分转换状态。
- 当前作品数据库 schema version 为 13：作品保留全剧创作简报、故事梗概、核心冲突、人物关系、结局方向、分集大纲、场次大纲和确认状态；每个集/短片单元拥有稳定 UUID、顺序、独立简报、剧本文本及状态；场次拥有稳定 UUID 和所属集关系，并保存可选的场次目标、冲突/转折和目标时长秒数；创作圣经支持作品定位、故事规则、时代、角色、地点、人物关系、道具、视觉基调和连续性事实，并保存类型字段、四类确定性状态、参考来源与用途；创作圣经条目、场次、剧本段落和语言版本均有独立修改快照；设定与多个剧集的引用仍使用稳定 ID。结构化剧本段落拥有稳定 ID、段落类型、顺序、状态和可选场次关联，覆盖自由文本、场景标题/描述、动作、角色、对白、括号提示、旁白、画外音、音效、音乐和转场。剧本语言版本在每集内保存语言、版本分类、确认状态、来源版本 ID 和语义段落快照；译稿创建时从当前稿件固化原稿版本，允许独立编辑并保留与原文段落的对应关系。质量提示的忽略/已处理状态按作品保存。schema v9 增加设定变化影响记录，可保留来源设定、变更摘要、稳定剧集/场次/段落定位、匹配文本、未能判定范围及有意例外理由；schema v10 增加可持久化的作品归档状态；schema v10→11 增加稳定身份的手工镜头、镜头与剧本段落/设定关联、文字视觉参考及其多镜头/设定关联，并扩展影响记录的定位字段；schema v11→12 将影响复核状态扩展为“待复核”“已复核，保留当前内容”和“有意例外（必须填写理由）”；schema v12→13 增加 AI 生成任务表，保存任务类型/目标、服务配置快照、状态、上下文清单、最终请求文本、候选文本、错误和用量，不保存服务密钥。schema version 1–12 均逐版本迁移，每次迁移前在 `backups/migrations/` 生成并校验 `VACUUM INTO` 快照。迁移或备份失败时回滚并保留可恢复原件。当前设定影响扫描按名称和字段值字面搜索剧本段落，并按已建立的稳定关系定位镜头与文字视觉参考；命中只提供人工复核线索，未命中或未关联不得解释为“没有影响”。该基础不包含图片导入/生成、完整分镜字段、语义冲突判断、连续性检查或媒体资产扫描，仍由 TASK-R002-011 及 RFC-003 后续验收。
- 多进程同时写同一作品不属于首版支持范围；存储层应检测写锁并清楚提示，不允许静默覆盖。
- WAL 仅用于确认过的本地文件系统部署。SQLite WAL 依赖同机共享内存，网络文件系统上的并发访问不作为支持场景。
- 首阶段备份可使用原型验证过的 `VACUUM INTO` 或 SQLite Online Backup API；开始备份前须协调应用内写入并纳入所有已提交事务。仅在完整成功并通过校验后才发布备份结果。

## 5. 备份和恢复

当前资料包基础采用目录式 `.sfpackage` v1，包含 `manifest.json`、SQLite `VACUUM INTO` 一致性快照，以及可选的 `media/originals`、`media/generated` 和 `media/derived`。清单为每个文件记录相对路径、大小和 SHA-256。导出先写入同级临时目录，成功后再重命名为最终资料包；不包含缩略图、缓存、临时文件、迁移备份或外部服务密钥。恢复先校验清单路径和所有文件哈希，再恢复到当前资料库中的新作品目录，为副本重新分配作品 ID，并保留原作品与原资料包。目录式封装便于当前阶段校验和移交；ZIP 等压缩容器未选定。

当前包中作品数据库仍完整包含剧本、创作圣经和历史，用户尚不能分别选择这些数据库内容；分镜、镜头、视觉参考、其他外部引用以及未纳入内容的缺失状态需随 RFC-003 资产关系交付后补齐。TASK-R002-019 的这些边界未完成前，不宣称满足完整资料包要求。生命周期复制与移除前备份使用完整持久文件清单，将数据库、媒体和其余非缓存文件一起校验；临时文件、缩略图及数据库锁文件不纳入。作品归档状态写入作品数据库。

恢复时对缺失文件、格式版本过旧、重复作品 ID 和无法迁移数据给出可读结果。部分恢复须列出未恢复内容及原因，保留原始备份。

## 6. 删除和空间管理

删除作品前展示文件数、素材文件数和估算体积；确认时重新核对作品 ID、数据库各表内容摘要、1 MiB 以内文件内容摘要，以及较大文件的路径、大小和修改时间。范围发生变化时拒绝执行并要求重新预览；大文件不在预览期间同步全量读取，避免冻结界面。可在移除前创建完整资料包备份。确认后调用 Qt 系统回收站能力移出作品资料库；若回收站不可用或文件被占用，保留原作品并报告失败。外部服务已收到的数据不受本地删除控制。

项目空间不足时，阻止新的大型媒体写入前显示所需空间和可选位置；不得通过清理原始素材来自动腾出空间。可以单独清理可再生的临时预览和缩略图，并展示其可再生成属性。

## 7. 阶段 0 原型证据与边界

TASK-R002-000 使用 [作品存储原型](../../app/prototypes/storage-probe/README.md) 验证了本机 NTFS 下的中文目录、SQLite WAL、事务保存、迁移成功/回滚、同进程连接写锁竞争、只读连接和 NTFS 拒绝写入 ACL、父目录缺失失败、容量上限故障、`VACUUM INTO` 备份校验、恢复及同卷移动后重开。容量上限由 `PRAGMA max_page_count` 模拟，不会实际占满用户磁盘；因此实际卷空间耗尽和系统级崩溃恢复仍由后续存储集成测试验收。

原型环境为 Windows、NTFS、Qt 6.11.2、SQLite 3.53.4 和 MinGW 15.2.0。网络共享、同步盘、可移动磁盘、跨卷移动与多进程写入未经验证，首阶段均不承诺支持。原型验证不替代作品界面中的保存状态、失败恢复和用户提示验收。
