# 完整产品阶段路线

本路线把 RFC-001 至 RFC-008 的长期能力安排为可验收的工程阶段。阶段顺序服务于依赖管理，不构成发布日期承诺；任何范围变更应同时更新 RFC 与本路线。

RFC-001 的 P0/P1/P2 是产品价值优先级，不直接决定发布阶段。用户确认的首阶段顺序优先完成剧本、分镜、参考图和基础媒体工具；视频、声音和剪辑虽属于产品目标，仍按本路线后续阶段交付。

## 阶段概览

| 阶段 | 主要交付 | 验收门 |
|---|---|---|
| 0. 技术验证 | Qt/QML+C++20 构建原型；SQLite 作品目录；文本/图片服务最小调用；FFmpeg 探测抽帧；剧本文档格式试验；许可清单 | 技术风险有原型结果、依赖和许可证审查结论；可安装空壳能打开本地示例作品 |
| 1. 创作基础 | 剧本、创作圣经、分镜、参考图、版本与检查、资料包、媒体探测/抽帧/预览 | 满足 [首阶段开发规格](phase-1.md) 中 PH1-AC-001 至 PH1-AC-024 |
| 2. 镜头生成 | 文生/图生视频、实拍感/2D/3D/动态漫画、逐镜头和批量候选、连续性审查、服务限制与消耗提示 | 批量任务逐项状态、取消/重试和部分结果保留通过 RFC-004 验收 |
| 3. 声音与本地化 | 角色对白、授权声音克隆、音乐/音效、口型同步、字幕、英文翻译和语言版本 | 授权、撤销、逐句预览、版本隔离和语言一致性通过 RFC-005/007/008 验收 |
| 4. 时间线与成片 | 多轨时间线、逐帧剪辑、代理、多机位、字幕/声音编排、基础调色、通用导出和平台预设 | 通过 RFC-006/007 的基础时间线、恢复、输出和媒体兼容验收 |
| 5. 专业后期与扩展平台 | 运动跟踪、稳定、复杂遮罩/抠像、动态图形、HDR/示波器、复杂混音；后续 macOS/Linux 支持评估 | RFC-006 专业级验收覆盖完成；各平台安装、媒体运行时和支持边界分别通过 |

## 需求阶段映射

下表定义需求的计划交付阶段，不代表已实现。阶段 1 的详细需求到验收映射见 [首阶段开发规格](phase-1.md)。阶段 2–5 的实现开始前，必须把表中需求进一步拆到该阶段的验收项；同一跨领域需求按表中明确的能力范围逐步扩展。

| 阶段 | RFC 需求范围 |
|---|---|
| 1. 创作基础 | RFC-001：REQ-PROJ-001–015、REQ-BIBLE-001–007、REQ-SCRIPT-001–010、REQ-BOARD-001–007；创作圣经引用规则及 REQ-AI-001–012、REQ-ASSET-001–007、REQ-CHECK-001–005 仅覆盖文本、图片和本地素材；RULE-001–008；NFR-DATA-001–006、NFR-I18N-001–002、NFR-A11Y-001及阶段适用的NFR-A11Y-003、NFR-PRIV-001–002。RFC-002：REQ-PROJECT-001、REQ-STORY-001–006、REQ-BRIEF-001–005、REQ-BIBLE-001–008、REQ-SCRIPT-001–010、REQ-QUALITY-001–006、REQ-DOC-001–012、RULE-STORY-001–005，跨模态影响仅覆盖本阶段交付内容。RFC-003：REQ-SCENE-001–005、REQ-SHOT-001–008、REQ-VIS-001–008、REQ-CONT-001–007、REQ-CTX-001–004，后续模态影响按阶段扩展。RFC-006：REQ-MEDIA-001、003、006、008–009、011–013，仅定义探测、预览和抽帧的支持范围。RFC-007：REQ-DEL-022–023。RFC-008：REQ-PRIV-001–017、REQ-RIGHTS-001–009、REQ-LABEL-001–003、REQ-RISK-001–008、REQ-TRACE-001–005，均限于首阶段支持的内容类型。 |
| 2. 镜头生成 | RFC-001：REQ-VIDEO-001–011；RFC-004：REQ-VGEN-001–006、010–016、020–026、030–035、REQ-ANIM-001–007、REQ-FAIL-001–005。将 RFC-001 的 REQ-AI-001–012、REQ-ASSET-001–007、REQ-CHECK-001–005，以及 RFC-008 的 REQ-PRIV-001–017、REQ-RIGHTS-001–009、REQ-LABEL-001–003、REQ-RISK-001–008、REQ-TRACE-001–005 扩展至视频/动画任务和资产；覆盖逐次发送范围确认、已知数据处理信息、授权撤销及发送记录。 |
| 3. 声音与本地化 | RFC-001：REQ-AUDIO-001–010、REQ-CAP-001–007；RFC-005：REQ-VOICE-001–006、REQ-DIALOG-001–007、REQ-CLONE-001–007、REQ-SOUND-001–008、REQ-LIPSYNC-001–006、REQ-LANG-001–005；RFC-007：REQ-SUB-001–008、REQ-LOC-001–007；RFC-008：REQ-VOICE-RIGHTS-001–005。将 RFC-001 的 REQ-AI-001–012、REQ-ASSET-001–007、REQ-CHECK-001–005，以及 RFC-008 的 REQ-PRIV-001–017、REQ-RIGHTS-001–009、REQ-LABEL-001–003、REQ-RISK-001–008、REQ-TRACE-001–005 扩展至对白、克隆声音、音乐/音效、口型和字幕任务及资产；覆盖逐次发送范围确认、已知数据处理信息、授权撤销及发送记录；落实 NFR-A11Y-002 对字幕和画面文字的适用检查。 |
| 4. 时间线与成片 | RFC-001：REQ-EDIT-001–005、REQ-EDIT-007–012、REQ-EXPORT-001–010、REQ-CHECK-006–008；RFC-006：REQ-EDIT-001–011、REQ-CUT-001–006、REQ-FX-001–005、007–010、REQ-MIX-001–006、REQ-MEDIA-002、004–005、007、010、012–013、REQ-SAFE-001–006；RFC-007：REQ-AR-001–007、REQ-DEL-001–010、012–021、024–029、032–033、REQ-QC-001–006；RFC-008：REQ-LABEL-004–012、REQ-TRACE-006，并扩展 REQ-RIGHTS、REQ-RISK 至成片交付。RFC-007 的 REQ-DEL-011 明确不属于产品发布能力。 |
| 5. 专业后期与扩展平台 | RFC-001：P2 专业扩展目标及 REQ-EDIT-006；RFC-006：REQ-EDIT-012–018、REQ-CUT-007–008、REQ-FX-006、011–017，以及专业媒体兼容和恢复场景。macOS/Linux 支持需单独评估，不因进入本阶段即视为承诺支持。 |

阶段范围以专题 RFC 的详细定义为准。若一个 RFC 需求跨越多阶段，阶段 1 或早期阶段仅实现表中明确列出的模态或操作；完成状态必须以该需求完整范围的验收为准。

**贯穿各阶段的体验要求**：RFC-001 / NFR-UX-001–004 适用于各阶段已交付的操作；NFR-A11Y-003 按各阶段实际提供的核心流程验收，不能用阶段 1 的结果替代后续剪辑、字幕和交付流程的验收。NFR-A11Y-002 随字幕、画面文字和叠加图形能力在阶段 3–4 验收。

## 关键依赖

1. 项目目录、资产 ID、版本和任务状态是所有功能的基础，应在阶段 1 前完成。
2. AI 候选/确认模型先用于文本和图片，再扩展到视频、音频，不允许每种能力各自发明状态规则。
3. 场次、镜头和资产关联先稳定，再进入批量视频生成和时间线编排。
4. 媒体引擎原型需在阶段 4 前通过，尤其验证高分辨率、代理、多轨播放、色彩和效果链。
5. 外部服务许可、费用、数据处理和内容来源应从首次集成即纳入任务记录，而不是等发布阶段补加。

## 阶段退出条件

- 每个阶段进入实施前，需求编号必须映射到该阶段验收项，或记录为后续阶段/明确不纳入；阶段验收不得以整份 RFC“部分实现”宣称完成。阶段 1 映射已列于 [首阶段开发规格](phase-1.md)，后续阶段的细项映射须在该阶段规格中补齐。
- 每个阶段执行离线场景、失败恢复、数据迁移、备份/恢复、许可审查和可访问性回归。
- 后阶段不得破坏既有作品格式；数据迁移须向前兼容策略、备份和失败回滚。
- 支持边界、未支持素材和外部服务限制在产品中可见，并有对应验收案例。
