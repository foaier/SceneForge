# 媒体管线与剪辑引擎

## 1. 首阶段范围

首阶段使用 FFmpeg/ffprobe 完成媒体探测和视频抽帧，并提供经过验证的只读预览。此阶段不实现多轨时间线、片段剪切、转场、滤镜、转码导出或专业特效；此限制是阶段安排，不删减 RFC-006 的完整产品目标。

导入后先检查文件存在性、文件大小和可读取属性。ffprobe 输出的时长、画面宽高、帧率、编码、音视频轨道、采样率和可识别色彩信息进入媒体属性记录；未知字段保持未知。抽帧结果为派生素材，保留源资产关联和生成任务信息。

本阶段的“预览”是只读查看能力：图片可查看静态画面，视频可在已验证范围内播放或查看抽取的关键画面，音频可在已验证范围内试听。预览不修改源文件、不代表支持时间线编辑或目标格式导出。ffprobe/FFmpeg 命令行适合探测和抽帧，不能仅凭命令可执行就推定播放稳定；预览所用解码后端、硬件加速和降级行为必须在阶段 0 的代表性素材上单独验证并写入兼容矩阵。

阶段 0 的兼容性原型应为首阶段形成可版本化的媒体能力矩阵。矩阵至少覆盖 MP4/MOV 容器中的 H.264/HEVC 视频、PNG/JPEG 图片、WAV/MP3/AAC 音频，以及损坏文件、长路径、旋转元数据、不同帧率、多轨音频和无视频流样例；逐项记录容器/编码、分辨率、帧率、时长/文件规模、色彩属性，以及探测、预览、抽帧的“已支持/有限支持/待确认/不支持”状态。矩阵未验证的项目必须显示未知或待确认，不得因能够读取文件就标为完整支持。

## 2. 子进程要求

- 使用 `QProcess` 的程序路径和参数数组调用，不拼接 shell 命令字符串。
- 子进程不得阻塞 UI 线程；必须显示任务状态，支持用户取消、超时终止和失败诊断。
- 输出写到作品目录临时路径，成功校验后再登记；失败/取消清理临时结果且不触碰输入素材。
- 输出目录必须在当前作品可控目录内；文件名、路径和参数要处理空格、非 ASCII 字符及特殊字符。
- 限制并发数和临时空间；批量操作支持逐项成功、失败和取消，不丢失已完成项。
- 记录 FFmpeg 可执行文件版本、构建配置、退出码和经脱敏的操作摘要；不在日志中暴露私密媒体内容。

典型探测调用使用 `ffprobe` 的 JSON 输出模式，例如读取 format 与 stream 信息；图片抽取按用户选择的镜头/时间位置生成独立图像。具体参数在媒体兼容性原型后锁定。

## 3. 媒体能力边界

应用应区分“可读取元信息”“可预览”“可抽帧”“可完整编辑”“可按目标规格输出”等能力。可导入或可探测不代表可稳定播放、完整编辑或无损导出。超出已验证范围的素材必须显示具体未知/限制字段，依据 RFC-006 / REQ-MEDIA-012–013 阻止把不确定能力描述为完整支持。

测试样例需覆盖常见 MP4/MOV、H.264/HEVC、不同帧率、旋转元数据、多轨音频、没有视频流、损坏文件、长路径和不支持编码。样例应有清楚的测试使用许可，不将用户素材用于测试。

## 4. 完整剪辑目标

专业编辑目标包括多轨时间线、逐帧精剪、代理媒体、多机位、转场、关键帧、字幕、调色、色彩信息、音频混音、跟踪/稳定、抠像、复杂遮罩和动态图形。首阶段媒体模块不应被设计成只能做静态命令执行；长期接口应区分：

- 媒体探测与解码能力；
- 实时预览和时间线播放能力；
- 时间线编辑模型及序列化；
- 效果节点/参数与关键帧；
- 渲染/导出与质量报告。

时间线使用帧率有理数和帧/时间码表达，不以浮点秒作为唯一编辑位置；23.976、29.97、59.94 fps 的 drop-frame 与 non-drop-frame 显示须明确。

## 5. 引擎决策门

不能把完整专业剪辑器建立在反复拼装 FFmpeg 命令的方式上。进入时间线阶段前须完成技术原型，对 MLT Framework、其他成熟媒体框架和自建组件的实时预览、代理、色彩管理、格式兼容、跨平台、复杂效果、许可证及打包成本进行比较。先通过 RFC-006 的代表性场景：四路多机位预览、Rec.709/HLG/PQ 处理、关键帧、跟踪/稳定、复杂遮罩和输出恢复。

OpenTimelineIO 可作为时间线交换模型候选；它不是视频解码器、实时播放引擎或特效渲染器。若采用，应明确支持范围及转入/导出损失，不将其误作底层媒体引擎。

在验证完成前，应用领域只依赖 `MediaEngine`、`TimelineCodec` 等抽象边界；实际引擎选型记录在 [技术决策记录](decisions.md)，并形成 ADR。

## 6. 发行许可

Qt 与 FFmpeg 的许可取决于所用模块、编译开关、二进制构建和应用分发方式。调用独立 FFmpeg 子进程本身不能消除重新分发该二进制的许可义务。发布前必须固定二进制来源和配置，生成第三方组件清单，完成 LGPL/GPL 及编解码专利适用性审查，并确定动态链接/替换能力、版权声明和源代码提供方式。

当前文档不批准分发任何特定 FFmpeg build，也不声称某个编解码器在所有国家和商业场景免费可用。
