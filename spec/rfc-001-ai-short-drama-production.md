# RFC-001：AI 短剧创作与成片制作产品需求

## 摘要

本 RFC 定义一款面向个人创作者、编剧和独立内容制作者的 AI 短剧创作与制作产品。产品应支持用户从创意开始，逐步完成作品设定、剧本、分镜、视觉素材、视频或动画、对白与声音、字幕、专业剪辑、质量检查和成片交付。

本 RFC 描述完整产品目标，并提供产品能力的相对优先级；它不承诺具体发布日期或版本安排。本文只定义用户需求、产品行为、业务规则和验收条件，不规定技术实现。

本文件是产品总纲。各领域的用户流程、状态、边界和验收条件分别由以下专题 RFC 详细定义；若专题 RFC 与本总纲存在冲突，应先修订并保持两者一致。

|---|---|---|

| RFC-003 | [场次、分镜与视觉资产 RFC](./rfc-003-storyboard-and-visual.md) | 场次结构化、镜头设计、镜头板、视觉参考图和连续性检查 |

### 编号与引用规则

RFC-001 是产品总纲，RFC-002 至 RFC-008 是专题需求。需求编号在所属 RFC 内有效；跨文档引用时必须同时写 RFC 编号和条款编号，例如“RFC-004 / REQ-VGEN-010”。总纲中的需求是产品级摘要，专题 RFC 中的需求是对应领域的详细定义。

## 1. 问题、目标与范围

### 1.1 要解决的问题

个人创作者需要在创意、剧本、人物、场景、分镜、图像、视频、声音、字幕和剪辑工具之间来回切换。内容一旦分散，角色和场景容易前后不一致，生成结果难以管理，返工和导出交付也容易出错。

### 1.2 产品目标

- **GOAL-001**：让用户能够从一句创意开始，完成可继续编辑的短剧作品。
- **GOAL-002**：覆盖从故事构思到可发布成片的主要创作和制作环节。
- **GOAL-003**：让 AI 帮助创作和制作，同时由用户决定正式内容、生成结果和最终交付版本。
- **GOAL-004**：支持实拍感短剧、二维动画、三维动画和动态漫画等视觉表达。
- **GOAL-005**：支持面向中国与海外短视频平台的创作和交付，并让用户自行调整平台参数。
- **GOAL-006**：让用户能够检查创作质量、内容来源、授权状态和发布标识要求。
- **GOAL-007**：让用户在没有网络连接时继续管理、编辑和交付本地作品；联网生成能力由用户选择。

### 1.3 范围

本 RFC 覆盖：

- 作品、剧集、场次、镜头和资产管理；
- 创意、故事、角色、世界观和创作圣经；
- 剧本、分镜、视觉参考图、视频和动画生成；
- AI 配音、授权声音克隆、口型同步、音效和音乐；
- 字幕、专业剪辑、多轨编排、调色、特效和媒体处理；
- 作品检查、平台发布准备、内容标识、授权追溯和导出交付。

当前目标用户是个人创作者和小型独立创作场景。本 RFC 不定义社交账号运营、内容排期、平台账号管理、播放数据分析或团队审批流程。用户可以导出资料供其他人员或工具继续制作。

### 1.4 产品优先级

优先级说明产品价值和依赖顺序，不删除本 RFC 已纳入的长期能力。

- **P0 创作闭环**：作品管理和本地可用、创意与创作圣经、剧本、场次和分镜、AI 候选审核、参考图、逐镜头视频生成、对白/字幕、基础剪辑、主流成片格式导出、来源和授权检查。
- **P1 完整制作能力**：动画和动态漫画的批量生成、角色声音与口型、多语言改编、多轨精细剪辑、调色、关键帧、常用合成和发布预设。
- **P2 专业扩展能力**：多机位、复杂遮罩、运动跟踪、稳定、进阶抠像、动态图形、复杂混音和广泛媒体格式兼容。
- **贯穿要求**：安全保存、来源追溯、外部服务授权、失败恢复和基本可访问性属于所有阶段的要求。

## 2. 用户与主要场景

### 2.1 首要用户

- 个人编剧、短剧创作者、独立动画创作者和独立内容制作者；
- 有创意但不熟悉编剧、分镜、剪辑或提示词写法的新手；
- 已有剧本、视频素材或制作经验，需要更完整创作工作流的进阶创作者。

### 2.2 主要场景

1. 用户只有一句故事想法，借助引导补充设定并逐步形成剧本。
2. 用户导入已有剧本，提取作品设定、场次和人物，再继续创作分镜。
3. 用户按照分镜逐镜头生成实拍感画面或动画，也可以在确认分镜后批量生成镜头候选。
4. 用户为角色生成对白、声音、口型和字幕，检查后编辑成片。
5. 用户对已有素材进行专业剪辑、特效处理、字幕制作和多画幅输出。
6. 用户生成交付资料并检查内容来源、授权状态与 AI 内容标识。

## 3. 术语

| 术语 | 定义 |
|---|---|
| 作品 | 一个短片或一部多集短剧的整体创作单元。 |
| 集 | 多集作品中的单集；单集短片可以不设集层级。 |
| 场次 | 剧本中具有连续地点、时间或行动关系的一段内容。 |
| 镜头 | 分镜中的单个视觉表达单位，可关联画面、运动、声音和时长。 |
| 创作圣经 | 作品中已确认的故事规则、角色、地点、关系、视觉基调和连续性事实集合。 |
| 视觉参考 | 用于说明角色、场景、构图、风格或氛围的图片或视频。 |
| AI 草案 | 尚未由用户确认、不得当作正式内容覆盖使用的生成结果。 |
| 发布预设 | 面向某个地区、平台或画幅的可调整创作与交付条件集合。 |
| 授权状态 | 资产或声音是否拥有、已授权、受限制、待确认或不可使用的记录。 |
| 帧率 / fps | 每秒显示的画面帧数；本 RFC 中 24、25、30、50 和 60 fps 是可选输出值。 |
| MP4 | 通用播放视频容器；本产品的基础播放预设包含 H.264 画面和 AAC 音频。 |
| H.264 / AVC | 常见视频压缩格式；用于定义基础播放交付兼容性。 |
| H.265 / HEVC | 常见高效率视频压缩格式；用于定义可导入素材的兼容范围。 |
| AAC | 常见数字音频压缩格式；用于定义基础播放交付兼容性。 |
| SRT / SubRip | 广泛使用的带时间位置字幕文本交换格式。 |
| WebVTT / VTT | W3C 定义的字幕和时间文本轨道格式。 |
| Fountain | 纯文本剧本交换语法，包含场景标题、动作、角色提示和对白等表达。 |
| FDX | Final Draft 剧本文档交换格式。 |
| ProRes / DNxHR | 用于高质量中间或母版交付的专业视频格式系列。 |
| C2PA | 用于表达数字内容来源和编辑历史声明的内容凭证规范。 |
| 1080p / 2160p | 按画面垂直像素数量表示的 Full HD 与 4K 级别输出。 |

## 4. 产品原则

- **PRIN-001 用户控制**：AI 生成结果默认先进入预览；用户确认后才能写入正式创作内容。
- **PRIN-002 逐步创作**：向导帮助新手完成流程，自由编辑和跳步对专业用户保持开放。
- **PRIN-003 可追溯**：生成、人工修改、授权状态和发布处理都应能追溯到相关内容或资产。
- **PRIN-004 可恢复**：失败、取消或重新生成不得无提示丢失已保存内容或覆盖已确认版本。
- **PRIN-005 用户可理解**：系统不要求用户掌握提示词、剪辑术语或完整影视制作流程才能开始。
- **PRIN-006 适应变化**：平台规则、内容要求和常用交付预设应可更新和调整。

## 5. 端到端创作流程

产品应支持但不强制用户按以下顺序创作：

`灵感或已有材料 → 作品设定与创作圣经 → 故事与剧本 → 场次与分镜 → 视觉资产 → 视频/动画镜头 → 配音与声音 → 字幕和剪辑 → 检查与多画幅交付`

用户可以从作品、剧集、场次、剧本文字、角色、素材或镜头任一层级开始或继续工作。系统应显示内容状态、待审核项和受上游变更影响的内容，不得强制用户完成一个机械式线性流程。

## 6. 功能需求

### 6.1 作品与创作入口

- **REQ-PROJ-001**：系统必须支持单集短片和多集短剧。
- **REQ-PROJ-002**：用户必须可以从一句自由描述、导入已有剧本、空白作品或创作模板开始。
- **REQ-PROJ-003**：新手引导必须支持题材、主题、受众、基调、目标时长、目标语言、平台方向和禁用内容等创作信息。
- **REQ-PROJ-004**：系统不得因为创意信息未填写完整而阻止用户开始创作；未知信息应可以跳过并标记为待决定。
- **REQ-PROJ-005**：系统可以针对影响较大的未知信息提出少量问题，并提供可选答案、自由回答和暂时跳过选项。
- **REQ-PROJ-006**：用户可以选择平台或自定义发布预设；预设参数可编辑，不能作为作品内容的强制限制。
- **REQ-PROJ-007**：作品支持独立的内容版本、创作状态、素材关联和交付选择。
- **REQ-PROJ-008**：多集作品应支持作品级设定和单集补充；跨集复用的角色、地点和事实应保持可查。
- **REQ-PROJ-009**：作品和用户导入的素材默认由用户在本地管理；未获得用户明确授权，不得将项目内容发送给外部生成服务。
- **REQ-PROJ-010**：网络不可用时，用户仍必须可以打开、创建、编辑、保存、整理和导出已有作品及本地素材。
- **REQ-PROJ-011**：用户可以选择可用的本地生成服务处理文本、图片、声音或视频；使用本地服务时，系统应明确说明该任务不会将输入发送到外部服务。
- **REQ-PROJ-012**：云端生成服务是可选能力；未配置或不可用时，不得阻断手工创作、媒体编辑和本地项目交付。
- **REQ-PROJ-013**：用户可以查看、备份、复制、恢复、归档和删除作品；删除前应显示将删除的作品和素材范围。
- **REQ-PROJ-014**：作品内容应有明确的已保存/未保存状态，并支持自动保存；自动保存失败时应及时提示用户。
- **REQ-PROJ-015**：用户可以将作品及所选素材导出为可备份、移交和重新打开的完整资料包。

### 6.2 创作圣经与连续性

- **REQ-BIBLE-001**：每个作品必须有可维护的创作圣经，包含作品定位、题材、主题、基调、故事规则、时代、地点、角色、人物关系、道具、视觉基调和连续性事实。
- **REQ-BIBLE-002**：用户可将每条设定标记为确定、暂定、待决定或禁止改变。
- **REQ-BIBLE-003**：AI 可以提出新增或修改设定的建议，但必须由用户确认后才能改变正式创作圣经。
- **REQ-BIBLE-004**：生成剧本、分镜、图片、视频、动画和声音时，用户可以查看所引用的相关设定。
- **REQ-BIBLE-005**：系统应检查角色身份、外观、关系、地点、时间、道具、故事规则和视觉风格在作品内是否冲突。
- **REQ-BIBLE-006**：一致性检查必须指出涉及的内容和冲突理由；系统不得自动修改作品事实。
- **REQ-BIBLE-007**：修改创作圣经或上游剧本后，相关下游内容应标记为待检查或可能过期；用户决定是否更新。

### 6.3 故事与剧本

- **REQ-SCRIPT-001**：系统必须支持故事梗概、主题、冲突、结局方向、人物小传、人物关系、人物弧线、分集大纲和场次大纲。
- **REQ-SCRIPT-002**：剧本正文必须支持场景标题、场景描述、动作、角色提示、对白、语气提示、旁白、画外音、音效、音乐提示和转场等内容。
- **REQ-SCRIPT-003**：用户可以人工创建、编辑、移动、复制、拆分和合并剧集、场次与段落。
- **REQ-SCRIPT-004**：AI 操作应支持生成、局部重写、续写、扩写、压缩、改写、风格调整、对白优化和选定文字解释。
- **REQ-SCRIPT-005**：用户无需编写提示词即可使用常见创作操作；有经验的用户可以查看和调整生成要求。
- **REQ-SCRIPT-006**：系统应支持多种短剧与影视剧本模板，兼顾可编辑、便于打印和通用剧本交换。
- **REQ-SCRIPT-007**：导入已有剧本时，系统应展示识别出的剧集、场次、角色、对白和动作，并允许用户修正解析结果。
- **REQ-SCRIPT-008**：系统应支持按作品、剧集、场次或选中文本生成多个候选；候选可以部分采用、合并、拒绝或保留为新版本。
- **REQ-SCRIPT-009**：剧本质量检查应提示缺少场次目标、冲突或转折、节奏异常、角色声音不一致、对白过长和未解决设定等问题。
- **REQ-SCRIPT-010**：剧本内容应支持集级和全剧级时长目标；系统可估算场次和全剧时长并提示差异，不得自动删改内容。

### 6.4 分镜与视觉预演

- **REQ-BOARD-001**：系统应能从剧本生成可编辑的场次信息，包括时间、地点、人物、道具、动作、情绪和连续性事实。
- **REQ-BOARD-002**：每个镜头必须支持编号、顺序、景别、构图、机位、镜头运动、画面动作、台词、声音、预计时长、画面描述和连续性备注。
- **REQ-BOARD-003**：用户可以新增、删除、排序、复制、拆分、合并或单独改写镜头。
- **REQ-BOARD-004**：用户可以为场次和镜头生成多张视觉参考图，并选择、比较、替换、重做、标记用途或删除。
- **REQ-BOARD-005**：视觉参考应能标明角色、地点、构图、道具、氛围或风格用途，并可复用于其他镜头。
- **REQ-BOARD-006**：系统应识别分镜中没有对应剧本依据的角色、地点或道具，以及镜头描述缺失、重复或与场次时长不匹配等问题。
- **REQ-BOARD-007**：用户应能在大纲、剧本、场次和分镜视图之间切换，并识别各视图是否同步、待审核或可能过期。

### 6.5 视频与动画生成

- **REQ-VIDEO-001**：系统必须支持以实拍感、二维动画、三维动画和动态漫画为作品视觉风格或镜头风格。
- **REQ-VIDEO-002**：用户可以从文字、分镜、视觉参考图或角色/场景设定发起视频或动画生成。
- **REQ-VIDEO-003**：用户可以单独生成一个镜头，也可以在确认分镜后批量生成镜头候选。
- **REQ-VIDEO-004**：批量生成必须保留逐镜头预览、接受、拒绝、重做和替换能力；部分失败不得影响已完成的镜头。
- **REQ-VIDEO-005**：用户可以设置镜头主体、动作、表情、背景、景别、机位、运动、节奏、风格和目标时长等生成意图。
- **REQ-VIDEO-006**：用户可以指定角色、地点、道具和风格参考；系统应帮助保持跨镜头视觉连续性，并展示可能不一致的结果。
- **REQ-VIDEO-007**：每个镜头可保存多个视频或动画候选，并支持查看、比较、选择和版本恢复。
- **REQ-VIDEO-008**：用户可以将静态参考图制作成动态镜头，也可以将生成镜头替换为用户导入素材。
- **REQ-VIDEO-009**：系统应显示生成任务状态、结果时长、适用限制、预估消耗或额度信息；用户可以取消或重做单项任务。
- **REQ-VIDEO-010**：系统不得承诺所有生成结果都完全符合剧本或跨镜头保持一致；应提供检查、重选和局部重做流程。
- **REQ-VIDEO-011**：视觉风格、角色身份和场景基准应可锁定或标记为重要参考；用户可确认后调整。

### 6.6 声音、配音与口型

- **REQ-AUDIO-001**：用户应可以为角色或旁白选择声音、语言、语气、情绪、语速和表达方式。
- **REQ-AUDIO-002**：系统应支持逐句或批量生成对白配音，并允许按句试听、修改文本、重做和替换。
- **REQ-AUDIO-003**：用户可以创建角色声音设定并在作品内复用；对白变化后，受影响的配音应标记为待检查。
- **REQ-AUDIO-004**：声音克隆仅可用于用户本人或已获授权的声音；开始克隆前必须收集明确授权确认，并保留授权状态和声音来源信息。
- **REQ-AUDIO-005**：系统不得提供未经授权的真实人物声音冒用功能；用户撤销授权后，后续使用必须停止并提示相关已生成资产。
- **REQ-AUDIO-006**：系统应支持生成、导入、剪辑和管理音效、环境声、音乐和片头片尾声音。
- **REQ-AUDIO-007**：音乐、音效和配音应能关联到场次、镜头或时间位置，并记录来源与授权状态。
- **REQ-AUDIO-008**：系统应支持对白与角色画面的口型同步，提供逐句预览、同步调整和替换能力。
- **REQ-AUDIO-009**：口型同步失败或用户取消时，原始画面和音轨必须保持不变。
- **REQ-AUDIO-010**：系统应支持不同语言版本的配音与声音选择；翻译和配音不得覆盖原语言内容。

### 6.7 专业剪辑与特效

- **REQ-EDIT-001**：系统必须支持多轨视频、声音、音乐、字幕、图像和文字素材的时间线编辑。
- **REQ-EDIT-002**：用户应能逐帧或按时间位置剪切、拆分、裁切、移动、排序、复制、拼接、替换、冻结、变速和删除片段。
- **REQ-EDIT-003**：系统应支持场景转场、叠加、画中画、标题、片尾、图形和字幕样式编排。
- **REQ-EDIT-004**：用户应能对位置、缩放、旋转、透明度、裁切、音量和效果参数设置随时间变化的关键帧。
- **REQ-EDIT-005**：画面处理应支持基础画面调整、色彩校正与调色、常用滤镜、模糊、遮罩、合成和抠像。
- **REQ-EDIT-006**：完整产品目标应支持运动跟踪、画面稳定、复杂遮罩、动态图形和进阶抠像等专业特效流程。
- **REQ-EDIT-007**：音频编辑应支持多轨混音、音量自动化、淡入淡出、对白与音乐平衡、音频同步和常见音频处理。
- **REQ-EDIT-008**：用户应能在编辑过程中预览结果，发现剪切空隙、音画不同步、声音过载、字幕遮挡和画面安全区问题。
- **REQ-EDIT-009**：剪辑操作应支持撤销、重做、版本对比和恢复；对源素材的编辑不得无提示覆盖原始内容。
- **REQ-EDIT-010**：系统应支持项目内的素材转换、压缩、裁切、画幅调整、音视频提取、关键画面提取、片段拼接和批量媒体处理。
- **REQ-EDIT-011**：媒体处理任务应显示进度和结果；失败、取消或格式不兼容时，应说明原因并保留输入素材。
- **REQ-EDIT-012**：系统应提供适合短剧创作的专业工作流程；常用操作可发现，新手能完成基础剪辑，熟悉剪辑的用户可使用高级工具。

### 6.8 字幕、翻译与语言版本

- **REQ-CAP-001**：系统应能从对白或音频生成带时间位置的字幕草案，并允许逐句编辑、拆分、合并和调整时间。
- **REQ-CAP-002**：用户可为字幕设置说话人、样式、位置、强调方式和显示安全区域。
- **REQ-CAP-003**：系统应支持字幕翻译和双语字幕；用户可以对照原文修改译文。
- **REQ-CAP-004**：字幕、剧本和配音版本必须独立管理；任何翻译均不得覆盖原始语言内容。
- **REQ-CAP-005**：用户应能选择将字幕作为独立字幕文件交付，或作为画面的一部分呈现。
- **REQ-CAP-006**：字幕应支持常用时间字幕交换格式；系统应检查超出画面、超出显示安全区、行长过长和时间冲突等问题。
- **REQ-CAP-007**：系统应支持可读性选项，包括字体大小、对比度、背景、字幕位置和可选的无障碍字幕信息。

### 6.9 画幅、发布预设与交付

- **REQ-EXPORT-001**：系统必须支持竖屏、横屏和方形项目画幅。
- **REQ-EXPORT-002**：用户可以从一个项目生成多个画幅版本；系统应提供重新构图建议并预览裁切结果，用户可以手工调整关键画面。
- **REQ-EXPORT-003**：平台预设可以提供时长、画幅、字幕安全区、语言、文件大小和内容提示；预设应可更新、自定义和覆盖。
- **REQ-EXPORT-004**：系统应支持单集短片和多集连续短剧的成片、剧本、字幕和素材资料交付。
- **REQ-EXPORT-005**：用户可以选择交付剧本、人物表、创作圣经、场次表、分镜、参考图、成片、字幕、声音、素材清单、授权汇总和内容检查结果。
- **REQ-EXPORT-006**：用户应能交付可继续编辑的资料包和便于播放、观看或打印的成品。
- **REQ-EXPORT-007**：导出前应显示所选画幅、语言、字幕、AI 标识、授权待确认项和内容检查结果。
- **REQ-EXPORT-008**：系统应提供成片预览和导出质量检查；如发现问题，应指出位置并允许用户返回修正。
- **REQ-EXPORT-009**：导出失败不得改变或删除当前作品；用户应能再次导出或调整交付选项。
- **REQ-EXPORT-010**：本 RFC 定义发布就绪文件的创作、检查和导出，不包含直接发布到社交账号、内容排期或平台账号运营。

### 6.10 AI 交互与生成控制

- **REQ-AI-001**：系统应同时提供结构化创作操作和围绕当前作品内容的上下文助手。
- **REQ-AI-002**：用户可以从选定作品、剧集、角色、场次、段落、镜头或素材发起操作。
- **REQ-AI-003**：生成前，用户应能查看将使用的创作上下文、目标内容位置和生成范围。
- **REQ-AI-004**：对话助手的建议不得自动变成正式内容；当用户要求生成或写入内容时，必须进入预览和确认流程。
- **REQ-AI-005**：系统应支持生成多个候选、比较差异、部分采用、合并、拒绝、重试和恢复。
- **REQ-AI-006**：生成过程应记录所用提示、内容上下文、服务来源、生成时间、结果和用户修改记录。
- **REQ-AI-007**：用户在未配置或未使用生成服务时，仍应能继续创建、编辑、整理和导出内容。
- **REQ-AI-008**：用户可选择适用于文本、图片、视频、语音或音乐任务的生成服务，并查看其能力、适用限制、费用或额度、内容处理说明和已知使用权限制。
- **REQ-AI-009**：首次使用外部服务前必须获得用户授权；之后每次任务前仍应显示本次会发送的内容范围，授权可撤销。
- **REQ-AI-010**：系统不得未经同意将完整作品、私人素材或无关项目内容发送到外部服务。
- **REQ-AI-011**：当服务的实际费用或额度无法准确预估时，系统应如实说明不确定性，不得呈现为确定价格。
- **REQ-AI-012**：生成、剪辑或转换任务可以取消；部分完成的结果应保留且明确标记状态。

### 6.11 素材、授权与资产来源

- **REQ-ASSET-001**：用户可以导入图片、视频、音频、字体、文档和其他创作参考素材。
- **REQ-ASSET-002**：每项素材可以关联作品、剧集、场次、镜头、角色、地点和交付版本。
- **REQ-ASSET-003**：素材应能记录来源、作者或所有者、授权状态、使用限制、到期条件、取得时间和备注。
- **REQ-ASSET-004**：用户可以把授权状态标记为已确认、有限制、待确认或不可使用。
- **REQ-ASSET-005**：AI 生成的文字、图片、声音和视频应保留来源、生成时间、生成要求和关联输入信息。
- **REQ-ASSET-006**：交付前系统应汇总无来源、授权受限、待确认或不可使用的资产；提示不得替代用户对权利状态的确认。
- **REQ-ASSET-007**：系统应保留原始素材和衍生素材的关联，使用户能够识别哪些成片或项目部分依赖某项资产。

### 6.12 内容检查、发布标识与合规提示

- **REQ-CHECK-001**：用户可以选择适用的内容检查规则和目标发布预设。
- **REQ-CHECK-002**：检查应覆盖用户创作约束、人物/场景连续性、剧本与分镜冲突、声音和画面同步、字幕可读性、画幅裁切、素材授权和 AI 内容标识。
- **REQ-CHECK-003**：每条提示必须指出相关内容或资产、风险原因和可采取的处理方式。
- **REQ-CHECK-004**：普通内容质量提示默认不阻止编辑、保存或导出；法律或目标平台要求的必需标识应在导出前明确提醒用户处理。
- **REQ-CHECK-005**：用户可以标记提示已处理、忽略或重新检查；系统应保留选择和检查时间。
- **REQ-CHECK-006**：用户可以为生成内容添加或确认 AI 生成标识；导出前按所选地区和发布要求检查可见提示与文件来源信息。
- **REQ-CHECK-007**：系统应尽可能保留来源标识，并在发现素材转换、裁切或重新导出可能移除来源信息时提醒用户。
- **REQ-CHECK-008**：平台政策或标识要求应作为可更新的信息呈现，不得声称一次检查能够保证作品在所有地区永久合规。

## 7. 全局业务规则

- **RULE-001**：AI 草案、人工编辑内容、已确认内容和已归档版本必须可区分。
- **RULE-002**：AI 不得自动修改已确认内容或创作圣经；用户明确确认后才能提交变更。
- **RULE-003**：上游修改可以触发下游提示，但不得静默覆盖下游内容或已选候选。
- **RULE-004**：角色和设定一致性以用户确认的创作圣经为基准；用户可以确认例外或有意变化。
- **RULE-005**：作品时长、平台建议和质量提示属于创作参考；除适用的发布要求外，不自动改写用户内容。
- **RULE-006**：原稿、译文、生成版本、配音版本和成片版本必须可分别识别和比较。
- **RULE-007**：用户撤销外部服务授权后，后续请求不得继续发送项目内容；已发生的数据处理情况应依据服务说明展示。
- **RULE-008**：来源或授权未知的素材可以用于草稿；交付前必须明确提示相关风险。
- **RULE-009**：声音克隆必须有有效授权；没有授权的声音不能作为可供后续创作使用的声音设定。

## 8. 质量与体验要求

- **NFR-UX-001**：新手能从简单想法开始，界面应解释专业名词并提供可跳过的引导。
- **NFR-UX-002**：常用生成和编辑操作应可以直接针对选中内容发起，不要求用户手工搬运上下文。
- **NFR-UX-003**：生成、处理和导出期间应显示当前状态、进度、剩余步骤或可理解的等待说明。
- **NFR-UX-004**：错误提示应说明受影响的内容、是否保留输入和结果，以及用户可采取的下一步。
- **NFR-DATA-001**：保存、取消、生成失败和导出失败不得丢失已确认内容或源素材。
- **NFR-DATA-002**：作品应支持版本比较、恢复和创作分支；恢复前应显示会受影响的内容。
- **NFR-DATA-003**：用户应能查看作品、素材和生成结果之间的关联。
- **NFR-DATA-004**：本地作品在离线状态下仍应可打开和继续编辑；只有依赖外部服务的操作可以提示需要网络。
- **NFR-DATA-005**：备份和恢复流程应让用户确认备份范围、恢复目标和覆盖影响。
- **NFR-DATA-006**：用户在关闭作品或退出前应能识别未保存的修改；自动保存状态必须可见。
- **NFR-I18N-001**：中文为主要创作语言；英文可用于剧本翻译、配音、字幕和资料交付。
- **NFR-I18N-002**：中文原文和英文译文应并存，并支持逐段对照、修改和独立导出。
- **NFR-A11Y-001**：主要编辑、确认、预览和检查操作应具备清晰状态反馈、键盘可操作性、可读文本和可调节显示。
- **NFR-A11Y-002**：字幕、画面文字和叠加图形应提供可检查的对比度、字号、位置和安全区提示。
- **NFR-A11Y-003**：主要创作、审核、剪辑和交付流程应以 WCAG 2.2 AA 作为可访问性目标；无法直接适用的检查项应说明原因和替代体验要求。
- **NFR-PRIV-001**：用户应能明确知道外部服务将获得哪些内容、服务使用方式和可获知的保留或训练说明。
- **NFR-PRIV-002**：撤销授权后应停止新请求；系统不应将服务授权解释为作品全部内容的永久授权。

## 9. 交付成功定义

一个完整作品可以在同一工作流内形成并交付以下成果：

1. 用户确认的故事、创作圣经和剧本；
2. 可编辑的场次、分镜、视觉参考和生成镜头；
3. 可编辑的对白、配音、口型同步、音乐、音效和字幕；
4. 可继续编辑的剪辑项目及检查后的成片；
5. 按目标画幅、语言和发布场景制作的交付版本；
6. 作品中素材来源、授权状态、AI 内容标识和未解决风险的汇总。

是否达到交付要求由用户确认。系统的检查结果用于发现问题，不替代用户对故事、作品质量或权利状态的判断。

## 10. 验收标准

- **AC-001**：Given 用户只有一句创意，When 开始新作品，Then 用户可以继续创作，系统将关键未知项标记为待决定，而不要求先填完表单。
- **AC-002**：Given 用户选择多集短剧，When 新建剧集，Then 整部作品共享的角色和设定可以在各集引用，单集变化可以单独记录。
- **AC-003**：Given 用户提出修改创作圣经的要求，When AI 生成设定变更，Then 正式设定保持不变，直到用户确认候选变更。
- **AC-004**：Given 用户已有剧本，When 导入并识别结构，Then 用户可以检查和修正场次、角色、对白与动作的识别结果。
- **AC-005**：Given 一份剧本，When 生成场次和分镜，Then 每个场次和镜头都可编辑并可追溯到相关剧本内容。
- **AC-006**：Given 一份已确认的分镜，When 批量生成视频，Then 用户可以逐镜头查看和确认结果，单镜头失败或重做不影响其他已完成镜头。
- **AC-007**：Given 用户拒绝某个生成候选，When 返回正式作品，Then 已确认内容没有被该候选覆盖。
- **AC-008**：Given 上游角色设定改变，When 下游镜头引用旧设定，Then 系统提示受影响范围，但不自动覆盖镜头或参考图。
- **AC-009**：Given 项目选择动画视觉模式，When 生成多个场景镜头，Then 用户可以查看角色和画面风格是否一致，并局部替换或重做镜头。
- **AC-010**：Given 用户生成角色对白，When 选择配音和口型同步，Then 用户可以逐句试听、预览和修正；失败时原画面和声音保持可用。
- **AC-011**：Given 用户请求克隆一段声音，When 未提供本人或授权确认，Then 系统不允许生成可复用的克隆声音。
- **AC-012**：Given 用户剪辑已有素材，When 进行裁切、分割、调色、混音、遮罩或特效处理，Then 原始素材不被无提示覆盖，并可通过撤销或版本恢复。
- **AC-013**：Given 用户选择竖屏、横屏或方形交付，When 创建另一画幅版本，Then 可预览构图调整并手工修正被裁切的主体。
- **AC-014**：Given 成片包含对白，When 生成或翻译字幕，Then 用户可以逐句修改字幕及时间位置，原文和译文独立保存。
- **AC-015**：Given 某项素材授权状态未知或受限，When 用户准备交付，Then 系统列出该资产、来源和风险状态。
- **AC-016**：Given 所选地区或发布预设要求 AI 内容标识，When 用户导出，Then 系统提示适用标识并提供相应处理选项。
- **AC-017**：Given 用户首次使用外部生成服务，When 准备发送内容，Then 用户可以查看发送范围和服务说明并选择授权或取消。
- **AC-018**：Given 用户已授权外部服务，When 发起后续任务，Then 系统仍显示本次发送范围，且用户能够撤销授权。
- **AC-019**：Given 用户未使用生成服务，When 编辑作品，Then 用户仍能完成手工编辑和资料交付。
- **AC-020**：Given 一个编辑任务或导出任务失败，When 用户查看错误，Then 系统说明失败原因、输入和已完成内容状态，并允许重试或调整。
- **AC-021**：Given 用户选择完整资料包，When 导出，Then 资料包包含用户选择的剧本、分镜、视觉资产、声音、字幕、成片和检查汇总。
- **AC-022**：Given 用户修改英文译文，When 查看中文原稿，Then 中文内容保持不变并可独立导出。
- **AC-023**：Given 用户完成一项一致性或发布检查，When 查看结果，Then 每项提示都能定位到相关内容并说明理由。
- **AC-024**：Given 用户使用主要编辑流程，When 仅使用键盘或调整显示比例，Then 能完成核心编辑、确认和预览操作。
- **AC-025**：Given 用户断开网络，When 打开并编辑已有作品，Then 剧本、分镜、本地素材、剪辑和资料导出仍可使用。
- **AC-026**：Given 用户没有配置任何生成服务，When 编辑作品，Then 用户仍可完成并保存手工创作内容。
- **AC-027**：Given 用户发起外部生成，When 确认发送范围之前，Then 项目内容尚未提交给该服务；用户取消后不发生发送。
- **AC-028**：Given 用户执行作品备份和恢复，When 选择备份资料包，Then 系统在恢复前显示作品和素材范围，且用户可保留原作品副本。
- **AC-029**：Given 自动保存失败，When 用户继续编辑，Then 系统明确显示未保存状态并提供恢复保存的操作。

## 11. 行业规范与参考依据

以下资料用于确定产品层面的内容表达、交付兼容、可访问性和标识需求，不规定实现方式：

- **中国生成合成内容标识**：国家互联网信息办公室等部门《人工智能生成合成内容标识办法》，2025 年发布，2025 年 9 月 1 日施行。办法涉及文本、图片、音频、视频和虚拟场景的显式与隐式标识；产品需求据此要求来源追溯和发布前标识检查。具体适用责任应依实际服务角色和适用规则判断。<https://www.cac.gov.cn/2025-03/14/c_1743654684782215.htm>
- **字幕可交换性**：W3C WebVTT 规范提供带时间信息的字幕和文本轨道表达；产品应支持常见字幕交付和编辑需求。<https://www.w3.org/TR/webvtt1/>
- **可访问性**：W3C WCAG 2.2 的可感知、可操作、可理解和稳健等原则作为界面、字幕和内容可读性的参考；本 RFC 不宣称特定认证结果。<https://www.w3.org/TR/WCAG22/>
- **剧本交换**：Fountain 公开语法展示场景标题、动作、角色提示和对白等常见纯文本剧本结构，可作为通用剧本交换需求的参考之一；产品应保留多模板和多种交付形式。<https://fountain.io/syntax/>
- **剧本文档交换**：应明确支持 Fountain 和 Final Draft FDX 的导入导出，并提示不能无损转换的部分。
- **字幕交付**：应明确支持 SubRip (SRT) 和 W3C WebVTT (VTT) 的导入导出；SRT 是广泛使用的字幕交换格式，WebVTT 规范：<https://www.w3.org/TR/webvtt1/>
- **通用成片交付**：MP4/H.264/AAC 作为基础播放预设；H.264 视频编码建议参考 ITU-T H.264：<https://www.itu.int/rec/T-REC-H.264>
- **平台预设**：中国和海外平台的内容、画幅、时长和标识要求可能变化。产品应将平台规则作为可更新的发布提示，而非固定不变的剧本约束。

## 12. 明确不在本 RFC 中规定的内容

本 RFC 不选择桌面/移动/网页形态、操作系统、编程语言、框架、存储方式、模型部署或服务接口、媒体处理引擎、内部数据结构、开发计划、人员配置或部署方案。这些内容应由后续独立的开发和技术文档处理。

## 13. 待讨论事项

- **OPEN-001**：是否需要将多用户共同创作、评论、版本审批或团队交付纳入未来产品范围。
- **OPEN-002**：是否需要直接发布到社交平台或管理平台账号；当前 RFC 仅覆盖发布就绪成片及资料导出。
- **OPEN-003**：RFC-007 已列出首批目标平台；每个平台的具体时长、尺寸、帧率、文件大小和标识规则仍需依据其当前官方资料逐项核实，并注明更新时间。
- **OPEN-004**：专业剪辑项目与第三方工具之间的可编辑工程互换格式，以及已定义格式之外的扩展格式，应在目标用户兼容性验证后确定。
- **OPEN-005**：平台预设的具体时长、尺寸、码率和标识规则必须按目标平台当前公开资料核实；过期平台规则不能被视为有效的交付条件。
